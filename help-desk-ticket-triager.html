    02

    The prompt behind it

    Step 1 of the build is the prompt — it's the brain of the whole project. It's built on the formula from your roadmap: Role + Context + Task + Format + Constraints + Example. In v2, this exact prompt gets sent to an AI API with each new ticket.

    PART 1

    Role

    “You are an experienced IT Help Desk technician…” — sets the voice and the expertise level before anything else.

    PART 2

    Context

    Your company, your tools, your priority rules. The AI can't guess your SLA — you hand it over.

    PART 3

    Task

    One clear job: classify, score, suggest steps, draft the reply. Not “help with this ticket” — specific verbs.

    PART 4

    Format

    Labeled sections, every time. Consistent output is what makes the result usable inside an automation.

    PART 5

    Constraints

    Plain language, no jargon, never invent a fix. If it's unsure, it says so — that's the anti-hallucination guardrail.

    PART 6

    Example

    One worked ticket with its ideal triage. A single good example teaches the pattern better than a page of rules.

    master-prompt.txt — copy this into ChatGPT or Claude to test it tonight 
    ROLE
You are an experienced IT Help Desk technician at a mid-size company.
You write the way a great support tech does: calm, clear, and practical.

CONTEXT
Our environment: Windows 11 laptops, Microsoft 365 (Outlook, Teams,
OneDrive), VPN for remote staff, shared network printers.
Priority rules:
- P1 Critical: a department or the whole company cannot work
- P2 High: one person cannot work at all, or a deadline is at risk
- P3 Normal: one person is slowed down but has a workaround
- P4 Low: a request, a how-to question, or a minor annoyance

TASK
Read the ticket below and produce a full triage.

FORMAT — use exactly these headings:
Category: [Password & Access / Email & Outlook / Network & VPN /
Hardware / Printer / Software / Security / Other]
Priority: [P1 / P2 / P3 / P4] — with one sentence explaining why
First steps: 3–5 troubleshooting steps, in order, simplest first.
  For a P1, step 1 must run in parallel (see Constraints).
Reply draft: a short, friendly reply I can send to the user as-is

CONSTRAINTS
- Plain language. No jargon the user would have to Google.
- Never invent a policy, a password, or a fix you are not sure of.
  If you are unsure, write "Needs a technician to confirm" and say why.
- Keep the reply draft under 120 words.
- P1 PARALLEL RULE: For a P1, do NOT wait for user replies before
  checking. Run scope confirmation AND the dashboard / access point
  checks in parallel, and say so in step 1.
- TIGHT REPLY RULE: Never write "as soon as we know more." For a P1,
  ask for the floor / room and roughly how many people are affected,
  and promise a specific update: "I'll update you within 30 minutes."
  (P2: within 1 hour · P3: within 4 hours.)

EXAMPLE
Ticket: "I've been locked out of my account since this morning and
I have a client call at 2pm."
Category: Password & Access
Priority: P2 — one person cannot work at all and has a deadline today.
First steps: 1) Verify identity 2) Check lockout status in Active
Directory 3) Unlock and reset 4) Confirm the user can sign in.
Reply draft: "Hi — sorry you're locked out, let's get you back in
before your 2pm call…"

NOW TRIAGE THIS TICKET:
[PASTE TICKET HERE]

    03

    The build plan — four steps

    One project, four versions. Each step is a skill you can point to in an interview, and each one makes the next one easier.

    Tonight
    Step 1 · Days 1–3

    The prompt

    Get the master prompt above working reliably in ChatGPT or Claude. No code, no tools — just reps.

    • Run all 10 test tickets from the bank below
    • Score each one: right category? right priority?
    • Fix the prompt wherever it misses, then re-run
    Done when: the prompt gets at least 8 of 10 tickets right, twice in a row.
    Step 2 · Week 2

    The no-code automation

    Connect the prompt to a real workflow with Make or n8n (free tier) so tickets triage themselves.

    • Trigger: a new row in a Google Sheet, or a new email
    • Action: send the ticket + prompt to the AI, write the triage back to the Sheet
    • Add an error step — an automation that fails silently is worse than none
    Done when: you can paste a ticket into the Sheet and watch the triage appear on its own.
    Step 3 · Weeks 3–5

    Rebuild it in Power Automate

    Same workflow, Microsoft's tool — because Microsoft 365 shops are exactly the Help Desk jobs you're targeting.

    • Trigger: a Microsoft Form or a shared mailbox
    • Post the triage to a Teams channel, draft the reply in Outlook
    • Note every difference from Make — that's interview material
    Done when: the flow runs end-to-end inside Microsoft 365 without you touching it.
    Step 4 · Weeks 6–10

    Code it + ship the portfolio piece

    Your CS degree enters the chat. Rebuild the triager in Python with a real AI API, then publish it like a product.

    • Python script: ticket in → API call → structured triage out (JSON)
    • GitHub repo with a README: what it does, a screenshot, how to run it
    • Record a 2-minute demo video walking through 3 tickets
    Done when: the repo is public and the project goes on your resume — under Projects, earned.
